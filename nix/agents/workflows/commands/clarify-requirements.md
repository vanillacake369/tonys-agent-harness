요청을 PRD 수준의 명세로 구체화한다.

# Task
$ARGUMENTS

# Workflow
1. 요청을 한 문장으로 요약하고 이해가 맞는지 확인한다.
2. 저장소를 조사해 코드로 답할 수 있는 질문은 먼저 확인한다.
3. 한 번에 하나씩 목적, 사용자, 범위, 예외, 비기능 요구사항, 성공 기준을 질문한다.
4. 각 Requirement ID에 우선순위와 검증 가능한 수용 기준을 붙인다.
5. 가정, 미결정 사항, 신뢰도를 분리한다. 확정 전에는 구현으로 넘어가지 않는다.

# Output
PRD, requirement-to-component traceability, acceptance criteria, open questions, and explicit non-goals.
